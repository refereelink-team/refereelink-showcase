# Guided multi-view adjudication

The right-hand inspector demonstrates adjudication through the most consequential facts first. Case review statuses, state filtering, persistence controls and review history are absent from this demo. It uses the existing synchronized evidence player and the upstream rule service; it does not replace either with a separate demonstration implementation.

## Review flow

1. **Action:** review the preselected offence and action suggestions. Tackle, standing tackle, holding, pushing, elbowing and challenge offer an editable **Contact** preset in a compact summary. High leg, dive and unrecognized actions do not presume contact. A confirmed no-offence answer goes directly to the result.
2. **Severity:** review the preselected carelessness, recklessness or excessive force suggestion. **Ball in play** is offered as an editable preset, rather than a repeated mandatory question. A dive omits the irrelevant intensity question. The flow continues to the location supplement by default; confirmed no-offence, dive or dead-ball paths go directly to the result.
3. **Location, optional:** mark a point on the existing pitch. Offender team and home-team defending direction appear only when penalty-area ownership is relevant. Coordinates, clear and undo retain the existing pitch controls.
4. **Context, optional:** identify ordinary play, stopping a promising attack (SPA), or denying an obvious goal-scoring opportunity (DOGSO). Whether the offender attempted to play the ball is requested only when it affects the outcome. Victim team and contact region are available under additional details.
5. **Recommendation:** distinguish conclusions supported by the confirmed facts from conditional outcomes. Missing-fact links return to the question that can narrow the recommendation.

Every core question permits **Unknown**. **Confirm and continue** explicitly accepts the current page's model suggestions and the displayed presets in one action. **Continue without confirming**, ordinary Next, Back and Skip do not confirm facts or save a revision. The default physical-offence flow visits both supplement pages; their fields may remain blank. Skipping an optional page preserves any values already entered. Every case switch starts a blank demonstration, including returning to a previously visited case. Model decisions, manual facts, location, overrides, guide step and playback attribution are cleared. Browser reload and **Restart** also clear the demonstration. Earlier server analyses and saved reviews are not loaded. In-flight results from a previous visit are discarded. The synchronized cameras, timeline and Grad-CAM presentation remain independent of the guide.

## Suggestions and incomplete facts

Model suggestions are preselected but retain their unconfirmed state, source and confidence until the reviewer accepts or edits them. Known offence and intensity values use compact editable summaries, alongside the action and match-condition summaries. Unknown values retain the full choices. **Confirm and continue** confirms only this page's visible, nonblank model fields. Supplement pages retain **Accept this page's suggestions**. Manual changes use human provenance and are protected from later model prefill. Newly supplied suggestions receive a brief highlight. The complete model-recommended option also retains a soft animated spectrum fill and an AI badge, including after a reviewer chooses a different answer. Recommendation appearance is derived independently from the model decision, so it does not turn a human answer into an AI answer or confirm the model suggestion. Reduced-motion settings retain the color treatment while disabling movement. Scripted and rule-derived values do not receive model decoration.

Contact and ball-in-play presets are labelled **Preset**, not AI observations. They stay outside the draft and rule preview until explicit page confirmation, which records the reviewer's acceptance with human provenance. They apply only to empty fields in the current demonstration, never to existing answers or fields explicitly cleared to Unknown. Changing an action before accepting a preset recalculates its availability. Contact is a common review assumption for the listed physical-action classes, not a claim that those classes always require contact: attempted kicks/strikes and dangerous play can be offences without contact. A dead-ball answer remains available because disciplinary sanctions can still apply while the restart remains the previous decision. Position, teams, SPA/DOGSO and attempting to play the ball remain evidence-dependent rather than receiving convenient guesses. See [IFAB Law 12](https://www.theifab.com/laws/latest/fouls-and-misconduct/).

The result shows restart and sanction independently. A conclusion is definite only when the remaining unknown facts cannot change it. Conditional cards state their assumptions explicitly and merge equivalent outcomes. Three cards are initially visible; additional alternatives can be expanded. If the core facts are too sparse, the guide asks the most useful next question instead of enumerating every possible action.

Missing location never becomes a guessed coordinate. For example, a supported physical offence may produce a penalty recommendation **if it occurred in the offender's own penalty area**, and a direct free-kick recommendation otherwise. Other unresolved conditions remain visible. Unsupported rule paths are identified as requiring manual review rather than silently assuming contact.

The demo never saves a review or assigns a case lifecycle status. Incomplete, conflicting or conditional facts still produce honest conditional outcomes; they are not treated as a case awaiting confirmation. Optional facts that do not affect either conclusion may remain unknown. Confidence, camera weights, runtime diagnostics and the rule trace are available in the result's evidence disclosure.

## API and compatibility

The read-only POST endpoint at `POST /api/multiview/cases/{case_id}/review/preview` evaluates the current draft without creating a review revision. Its response contains `assessment`, `restart_resolution`, `sanction_resolution`, `scenarios`, `required_facts`, `optional_facts`, `next_fact` and `can_finalize`. Each resolution is `resolved`, `conditional` or `unavailable`; conditional scenarios retain their assumptions, outstanding unknowns and rule trace. The frontend debounces edits by 200 ms and discards responses from an earlier draft or case visit. A failed preview preserves the current demonstration facts and hides obsolete recommendations.

Preview uses the upstream rule-dependency logic. Hypothetical scenarios and fabricated locations are never written into the supplied facts. Preview does not invoke CUDA inference or a language model; conditional wording and final explanations use deterministic rule templates. The client calls analysis and preview endpoints only, with no review GET, PUT, history or saved-record explanation requests. The upstream persistence APIs remain compatible for other clients; existing records are neither loaded nor modified by the demo.

## Validation boundaries

Frontend regression checks run on macOS with `npm test`, `npm run lint`, `npm run format:check` and `npm run build`. Helper tests cover optional traversal, confirmed no-offence branching, legacy-value handling, page-scoped adoption, provenance and preview request generations. Browser acceptance additionally covers the short flow, skipped supplements, return links, case switching, keyboard interaction, narrow layouts and existing video synchronization.

Python rule and API checks run on the remote CUDA host. They must cover unknown location and ownership, SPA/DOGSO dependencies, irrelevant missing facts, unsupported paths, strict-save compatibility, unchanged input facts and non-persisting preview requests. These software checks do not establish model accuracy, sustained live frame rates or physical-device acceptance. User footage, runtime credentials and screenshots remain outside Git.
