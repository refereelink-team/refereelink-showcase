# BP-TWR-30 接入与实物验收

## 官方依据与支持边界

- [TWR-30 用户手册](https://doc.51uwb.cn/user_manual/twr-30/twr-30/)：HEX 测试、定位数据格式、定位操作与常见问题。
- [官方 Python 上位机手册 §10.2](https://doc.51uwb.cn/tools/Landian_UWB_TWR_Host_USER_MANUAL/#102-mr)：16 字节 `mr` v2、小端厘米单位、帧号及第四路处理。
- 厂商资料包由用户提供；下载和解压内容保留在仓库外，不分发厂商软件或密码。

Showcase 当前仅支持 **3 基站 + 1 个选定标签的同平面 2D 定位**，不是四基站 3D 解算。收到四路 `mr` 距离时仅使用地址 `0x0001/0x0002/0x0003`，忽略第四路。不支持 `mri`、文本协议或出厂单基站测距程序。UWB 与现有 Yahboom IMU 是两条独立串口；只接 UWB 即可定位，无需 IMU。演示数据不能用于实物验收。

## 1. 固件与模块

1. 先确认板卡型号、固件版本和模块数量。手册指出出厂程序为测距程序；单基站测距结果不能直接用于三基站定位。
2. 按官方“定位 HEX”或 `Location` 源码工程配置三个基站，地址依次为 `0x0001`、`0x0002`、`0x0003`。标签默认地址为 `0x0005`；不同地址需在页面中填写对应的十进制 ID。
3. 官方资料目录 `TWR-30-B资料 / 测试HEX 文件 / 定位` 包含以下四份 V1.2 预编译 HEX，已下载并检查文件格式。先核对对应板卡版本；不能仅凭名称认定硬件兼容，也不能把同一份文件刷到四块板上。
4. 编译配置见官方 `bphero_uwb.h` 的 `RX_NODE/TX_NODE`、`MAX_ANTHOR`、`SHORT_ADDR`、`LCD_ENABLE`。标签和基站地址不可重复。烧录、驱动和 ST-Link 接线以厂商手册为准；本项目不修改或自动烧录板端固件。

| 板子 | 官方定位 HEX | LCD |
| --- | --- | --- |
| A1（接电脑） | `BP30_STM32F1_RXNode_0x0001_Anthor1_LCDDisable_V1.2.hex` | 关闭 |
| A2 | `BP30_STM32F1_RXNode_0x0002_Anthor2_LCDDisable_V1.2.hex` | 关闭 |
| A3 | `BP30_STM32F1_RXNode_0x0003_Anthor3_LCDDisable_V1.2.hex` | 关闭 |
| T5（移动标签） | `BP30_STM32F1_TXNode_0x0005_LCDEnable_Tag_V1.2.hex` | 开启 |

在 Windows 使用 ST-Link 驱动和 STM32 ST-LINK Utility，断电连接板上 **SWD 下载口**：`SWCLK → CLK`、`SWDIO → DIO`、`GND → GND`。只有确认下载器的 3.3V 是供电输出时才用它连接板上 3.3V；`Vref/VTref` 可能只是电压检测输入。禁止把 5V 接到 3.3V 脚，不同时连接下载器与充电宝两路供电。按 `Target → Connect`、`File → Open file` 选择该板对应 HEX，再执行 `Target → Program & Verify`，校验成功后断开、断电拆线，逐板重复。不要随意更改读保护或 Option Bytes。烧录前准备匹配板卡的原厂恢复固件；本次四份定位 HEX 不包含 Distance 恢复固件。

另行下载的固件源码包包含 `Location` 与 `Distance` 两个 `HV2.0_SV2.1` 工程，解压校验通过。已核对 `Location` 的实际发送代码：`mr 02`、16 字节、小端厘米、LFCR 结尾，与本项目匹配。该工程默认编译为标签 0005、三个基站、标签 LCD 开启；不能不改角色就把同一个编译产物烧到所有模块。源码包本身未包含预编译 `.hex`，上述四份 HEX 来自独立的“测试HEX 文件 / 定位”目录，不能据此认定二者为同一构建版本。详见 [来源与校验和](PROTOCOLS.md)。

## 2. 供电与 UART

- 按厂商要求给模块 USB 接口供 **5 V**；不要使用串口线给模块供电。
- 连接上传定位距离的 **0x0001 基站**，不是标签，也不是其他基站。
- 厂商串口线：白线 RXD 接模块 TX，黑线 GND 接 GND；红线 +5V、绿线 TXD 不连接。换用其他转接器时按引脚标识与电平规格核对，不照搬线色。
- 串口参数为 **115200，8 数据位，无校验，1 停止位**。初始化正常为 `init pass`；`init fail` 应停止定位调试并按官方说明排查硬件。
- 先在串口助手 HEX 模式确认有 `6D 72 02` 开头的 16 字节定位帧，然后关闭串口助手和官方上位机，避免独占同一串口。

## 3. 放置与连接 Showcase

1. 三个基站非共线，建议等边三角形；标签在三角形内运动。模块竖直、固定、互相无遮挡，基站与标签同高。官方 FAQ 建议模块间距大于 50 cm、高于地面 30 cm。手册前文测距最小间距写 20 cm，实际布置采用 FAQ 更保守的建议；解析器的 20 cm 下限不是精度承诺。
2. 用米尺测量坐标，A1 对应 `0x0001`、A2 对应 `0x0002`、A3 对应 `0x0003`。默认坐标只是示例，必须替换为现场值。
3. 串口读取发生在 **Python 后端所在的 Linux 主机**。将转接器接到该主机并授予运行服务的用户串口权限。浏览器所在的 Mac/Windows 串口不会被远程后端自动读取；本项目没有串口转发桥。
4. Linux 上可用 `ls -l /dev/serial/by-id/` 查找稳定路径，或使用 `/dev/ttyUSB0`、`/dev/ttyACM0`。不要把串口改为全员可写，也不要把真实设备标识写入 Git。
5. 打开“足球定位”→“设备数据”，停止演示后填写 UWB 路径、标签 ID（十进制）和实测基站坐标。未接 IMU 时保持 IMU 路径为空。
6. 点击“连接串口”会先保存当前坐标、标签和端口，再打开串口。参数只能在停止/断开后修改。配置目前保存在服务内存，后端重启后需重新设置。
7. `串口已打开`只代表端口打开成功；还需看到`有效数据`和持续更新的位置。拒帧数和最近原因用于软件诊断，历史原因不会因下一帧成功而自动清空。

`plane_height_m` 和三个 `z_m` 可通过 [配置 API](TELEMETRY_API.md) 一起设置为实际公共高度；页面仅编辑 XY。这个高度是安装元数据，不是传感器测得的 Z。

### 可拆足球展示布局

球内仅放固定、防松的 UWB 标签和充电宝；IMU 使用独立 Type-C 数据线接后端主机，留在球外。充电宝只供电，不会传出 IMU 数据；当前没有修改标签/基站固件来无线转发 IMU。先在桌面完成验收，再装球并检查供电稳定性与安装遮挡。展示时将球放在与基站近似同高的托架上小范围平移；滚动、踢球、腾空及抗冲击均未验证。球外 IMU 的加速度不是足球加速度，不能把两条独立数据说成融合结果。

## 4. 无定位时的排查顺序

| 现象 | 检查 |
| --- | --- |
| 端口不存在/无权限/被占用 | 后端主机上的路径、CH340 驱动、服务用户权限、关闭其他串口软件 |
| 串口已打开但数据过期 | 0x0001 基站、供电、定位固件、115200/8N1、TX/RX/GND 接线；只有初始化文本不能定位 |
| `invalid_uwb_framing` | 固件是否输出 `mr` v2，是否错用 `mri`/文本或测距固件，串口参数是否一致 |
| `unexpected_tag_id` | 标签烧录地址与页面十进制 ID 是否相同 |
| `uwb_range_out_of_bounds` | 前三路距离是否有效（20–3000 cm），基站是否全开、遮挡/超距/缺测 |
| `duplicate_or_out_of_order_sequence` | 重复或倒序帧；设备复位后先断开再连接，重置序列状态 |
| `inconsistent_range_geometry` / `position_residual_exceeded` | 距离单位、基站编号与实测坐标、同高条件、遮挡、天线延时 |

## 5. 实物验收（未完成前不声称硬件可用）

- 记录板卡/固件版本、三基站实际位置、供电与接线；私有设备标识与原始采集保留在 Git 外。
- 在串口助手核对真实 HEX 数据与本项目解析结果：标签 ID、帧号、前三路厘米值换算为米一致。
- 用测量点检查静止位置，再移动标签观察轨迹；记录实际位置误差。厂商标称精度不是本项目已验证精度，页面残差也不是实测误差。
- 断开串口后旧数据必须变为失效；重连、重启模块后再次验证数据恢复。
- 单独 UWB、UWB 与 IMU 并行分别验收；确认未启动演示模式。
- 当前仍显示 `hardware_verified=false`，不会因打开串口或通过软件测试而自动变成已验收。
