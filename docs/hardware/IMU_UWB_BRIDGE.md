# IMU 接标签 STM32，经 UWB 上传：分阶段方案

**状态：电脑端接入代码和可移植 C 协议模块已实现；不是可烧录固件，不代表无线链路已打通。** 默认仍用独立 USB，可在“足球定位 → 设备数据 → IMU 接入方式”中切换。切换前断开串口/停止演示；保存或连接会提交所选方式。页面不会刷写板子，也不会自动侦测固件。

## 1. 两种模式

| 页面选项 / API 值 | 球内 | 球外到 PC | 当前边界 |
| --- | --- | --- | --- |
| 独立 USB / `usb`（默认） | 充电宝 → T5 标签 | A1 USB 串口 + IMU Type-C，各自 attach 到 WSL | 现有接入；球外 IMU 的加速度不是足球的加速度 |
| 接标签 STM32，经 UWB / `uwb_bridge_v1` | 充电宝分别给 T5、IMU 供电；IMU UART → 标签 | 只有 A1 USB 串口 attach 到 WSL | 实验预接入，必须开发标签和 A1 配套固件；原厂 Location HEX 只传定位 |

A2/A3 保持原定位角色并独立供电。两种方式均只显示传感器轴、含重力的三轴加速度，不做姿态或 UWB/IMU 融合；三基站仍为同高二维定位。球内供电、固定、冲击和射频遮挡必须实测，不能直接用踢球/腾空作为首次验收。

## 2. 球内候选接线（先在桌面，断电接线）

```text
小充电宝 ── 合适的 USB 供电线 ── T5 UWB 标签
         └─ Type-C 供电线 ────── Yahboom IMU

IMU TX  ── 杜邦线 ── 标签 UART RX（源码 USART1 / PA10）
IMU GND ── 杜邦线 ── 标签 GND
IMU RX：暂不接，不把标签原有调试 TX 接入 IMU

标签 ── UWB 无线 ── A1 ── USB 转串口 ── 同一 PC 的 WSL 后端
```

- 官方 Location 源码 `STM32F1_UWB/Core/Src/usart.c` 配置 USART1 的 TX=PA9、RX=PA10、115200/8N1；官方 IMU STM32 教程示例使用另一组 UART，不能照抄 PA2/PA3 当作 TWR-30 的引脚。
- 按具体板卡的 **RX/GND 丝印** 找外部串口排针，不凭排针顺序或颜色猜测；不要误接 SWD。源码配置证明 MCU 的候选接口，不等于该批板卡外部连线已用实物确认。
- 供电 5V 不等于 UART 信号是 5V。Yahboom 官方示例可接 STM32F103，但这两块实物的电平、板载 USB-UART 是否同时驱动 RX 仍须核对。不得将 5V 电源接到 PA10 或 3.3V；若不兼容，应做电平转换而非硬接。
- 两块板各自通过电源接口供电，先只跨接 TX→RX 和共地；不互接电源脚。不同时把 IMU USB 数据接电脑作为第二条采集链路。
- 杜邦线适合桌面联调，装球前要可靠固定、防松、绝缘。小充电宝低负载自动关机和球内屏蔽影响没有验收。

官方依据及下载校验见 [协议证据](PROTOCOLS.md)，IMU 初始化、默认 25 Hz 和 USB 基线验收见 [IMU 指南](IMU_SETUP.md)。本轮不修改原厂 HEX。

## 3. 自定义 RL bridge v1 协议（不是厂商协议）

保留 A1 原有 **16 字节 `mr 02` 定位帧**，另发 **36 字节 `mi 01` IMU 帧**。A1 必须将每帧完整排队输出，不能让日志或另一条消息的字节插入帧中间。不要把原始 `7E 23` 直接拼到串口上，也不要改变原来的 `mr` 长度。

| 字节偏移 | 内容 |
| --- | --- |
| 0–1 | ASCII `mi`（`6D 69`） |
| 2 | 版本 `01` |
| 3 | 来源标签 ID，1–255，本次为 `05` |
| 4–5 | IMU 样本序列号，uint16 LE，每个新采样递增、65535→0 回绕 |
| 6–9 | 标签接收该采样时的毫秒计数，uint32 LE，可来自 HAL_GetTick |
| 10 | 载荷长度 `17` hex，即 23 字节 |
| 11–33 | 完整 Yahboom `7E 23 17 04 … sum8` 原始帧，内层校验保持不变 |
| 34–35 | 字节 0–33 的 CRC-16/CCITT-FALSE，uint16 LE |

CRC 参数：poly=0x1021、init=0xFFFF、无反射、xorout=0；`123456789` 的校验值应为 `0x29B1`。加速度仍按 `raw × 16 / 32767 × 9.80665` 换算。其他 IMU 功能帧不封装成加速度。

后端用一个有界缓冲器先分离完整 `mr`/`mi`，再交给各自解析器，避免把有效 IMU 载荷里的 `mr` 当定位。已识别的 36 字节 `mi` 候选即使版本/长度/CRC 错误也整包丢弃，不重新解释其内层字节；插删字节可能使紧随其后的一个包也被丢弃，后续包可重新同步。原厂 `mr` 本身仍无校验，不能因此宣称整条链路防误码或可认证来源。

两条逻辑数据各自检查标签、序列和有效时间；IMU 的外层 CRC 与内层 sum8 都必须通过。重复/逆序 IMU 包不刷新有效状态；错误 IMU 不阻断定位。只收到原厂定位帧时，定位可显示，但 IMU 仍过期/无效，不会自动启动回放。包级分帧错误显示在“A1 分帧拒绝”，样本拒绝显示在 IMU/UWB 各自计数。USB 模式也在 A1 输入上按完整包划界，但忽略桥接 IMU，避免切回 USB 后将残留桥接载荷误认成定位帧。

HTTP 的 `timestamp` 是后端接收时间，`sample_ms` 只是标签上电时钟，不是与视频/UWB 同步的绝对时间。到达有效不证明样本端到端延迟。标签重启、序列大跨度丢失后应手动断开再连接，重置两个序列及半包缓冲；无自动重连。`hardware_verified` 始终为 false。

## 4. 已交付的固件侧代码与还缺什么

`firmware/uwb_imu_bridge/bridge_protocol.h/.c` 是本项目独立编写的可移植 C99 编解码模块：

- `rl_bridge_encode()`：检查完整 23 字节原始帧、输出容量和标签，封装 36 字节包；失败返回 0，成功返回 36。输入与输出缓冲不得重叠。
- `rl_bridge_valid()`：供 A1 在转发前检查固定包长、版本、标签非零、CRC 和内层帧；不代替无线源地址授权/匹配。
- `rl_bridge_crc16()`：调用者须提供有效的输入缓冲及长度。

软件测试用主机 C 编译器以 `-std=c99 -Wall -Wextra -Werror -pedantic` 编译，并与 Python 字节级交叉检查。这不是 ARM/Keil 工程编译，更不是已刷入 STM32。

下一阶段应在已下载的 **Location** 工程集成（原厂源码/HEX 不复制进本仓库）：

1. **标签串口接收**：在 USART1 / STM32 中断相关文件启用 RX 中断或 DMA，环形缓冲接收；主循环校验 IMU 帧。中断不等待完整包、不阻塞收发，溢出计数可诊断。
2. **标签快照**：只缓存最新有效 `0x04` 样本及采样序列/时间，线程/中断交换须一致；旧样本不能重新编号冒充新采样。先保持默认约 25 Hz，实际上传率受无线空闲窗口限制。
3. **标签无线发送**：`BP-UWB_LIB/Src/tx_main.c` 当前在测距后构建并发送 `M` 定位消息。新增独立消息类型（候选 `I`，当前检查的分支未使用），承载上述完整包；必须按实际无线结构重算帧长、缓冲容量、目的地址 A1 和 FCS。不要延长或改写原有 P/A/F 测距时间戳消息。
4. **A1 接收**：`BP-UWB_LIB/Src/rx_main.c` 的 switch 当前 `case 'M'` 只向 UART 转发 16 字节。新增 `I` 分支，验证无线帧长度、来源短地址与封装标签一致，再调用 `rl_bridge_valid()`，将完整 36 字节包排队输出。
5. **时序/串口发送**：不能在测距关键路径或无线中断中增加阻塞 UART 输出。用受控队列/DMA 或在明确空闲时段发送，定位优先；队列满时丢弃过期 IMU 并记数，不阻塞测距。需要实测 A2/A3 接收窗口、测距周期与新增发送的冲突，不能仅凭包短就保证刷新率。
6. **工程与实物**：核对板卡版本、角色/地址、三基站宏、LCD、Keil/ARM 工具链，再分别编译标签和 A1，生成各自 HEX 并保留官方恢复包。已检查的源码 HV2.0/SV2.1 与下载 HEX V1.2 的对应关系没有验证，不能假设直接替换。

**以上六项硬件集成尚未完成，不提供空函数或现成 HEX 冒充完整无线固件。** A2/A3 的测距角色不计划更改，但仍必须纳入联调验收。

## 5. 切换、恢复与验收顺序

1. 先在独立 USB 模式验收 IMU 与原厂 Location 定位，记下基线，保留恢复固件。
2. 配套桥接固件完成后，断电接两根信号线，桌面供电。只有 A1 接 PC 并 attach 到 WSL；关闭串口助手。
3. 页面停止回放/断开串口，选实验桥接，填 A1 的 `/dev/…`、标签 ID 5、实测基站坐标；保存或连接。隐藏的 IMU USB 端口会在配置提交时清空。
4. 分别观察定位与 IMU **有效数据**，不能只看“共用 A1 串口”。轻转 IMU，再只移动标签，检查数据来源与安装轴向；不是姿态融合或坐标标定。
5. 测试 IMU 停止、标签断电、A1 拔插、坏包、序列回绕和重新连接；验证对应数据过期、队列有界，比较接入 IMU 前后的定位更新率/丢帧。完成这些后再做球内安装测试。
6. 恢复独立 USB：断开串口，选 USB，重新填写 IMU 的独立 WSL 串口再连接。若 A1 仍输出桥接帧，USB 模式只读取独立 IMU，不读取 A1 中的桥接 IMU；不用反复刷固件来切网页模式。要恢复板卡本身则按原厂恢复流程另行烧录。

当前可执行的是代码层协议/PTY 测试与界面配置切换；步骤 2–5 的无线实物验收尚不可据此宣称通过。显式演示回放仍是独立 simulation，不证明桥接固件有效。
